## Описание проекта

Этот проект представляет собой учебный пример использования Java Reflection API для реализации механизма конфигурации приложения через аннотации. Проект демонстрирует, как с помощью Reflection API можно автоматически загружать значения полей из конфигурационного файла на основе аннотаций.

### Основные концепции, используемые в проекте:

1. **Аннотации** (`@AppConfig`) - пользовательские метаданные для пометки полей
2. **Reflection API** - механизм интроспекции классов во время выполнения
3. **Динамическое сканирование классов** - поиск аннотированных полей в пакете
4. **Автоматическая конфигурация** - установка значений полей из внешних источников

## Структура проекта

### Ключевые классы:

1. **`AppConfig.java`** - пользовательская аннотация для пометки полей, которые должны быть загружены из конфигурационного файла
2. **`AppConfigWorker.java`** - класс, использующий Reflection API для сканирования пакета и инициализации аннотированных полей
3. **`A.java`** - демонстрационный класс с полями, помеченными аннотацией `@AppConfig`
4. **`Main.java`** - главный класс приложения с точкой входа `main()`
5. **`config.properties`** - конфигурационный файл со значениями для полей

### Зависимости:

- **Reflections 0.10.2** - библиотека для сканирования классов в classpath

#### Требования к реализации:

4. **Обработка ошибок**:

#### Задание 2: Работа с генериками и параметризованными типами

**Цель:** Изучить обработку обобщенных типов через Reflection API, включая анализ параметризованных типов, определение фактических типовых аргументов и создание экземпляров обобщенных коллекций с правильными типами во время выполнения.

**Задача:** Создать класс `GenericAnalyzer`, который предоставляет следующие возможности с конкретными примерами реализации:

1. **Анализ параметризованных полей и методов:**
   - Создать тестовый класс `DataContainer<T, U extends Number>` с полями: `List<T> items`, `Map<String, U> metadata`, `Set<? extends Comparable<T>> filters`
   - Реализовать метод `analyzeGenericFields(Class<?> clazz)`, который находит все обобщенные поля и выводит:
     - Имя поля и его обобщенный тип
     - Фактические типовые аргументы (если доступны)
     - Ограничения типовых параметров

2. **Определение фактических типовых параметров:**
   - Создать класс `StringIntegerMap extends HashMap<String, Integer> {}`
   - Реализовать метод `extractTypeArguments(Object instance)`, который для экземпляра `StringIntegerMap` определяет:
     - `String` как тип ключа
     - `Integer` как тип значения
     - Иерархию типов для вложенных структур

3. **Создание экземпляров обобщенных коллекций:**
   - Реализовать метод `createGenericCollection(String collectionType, Class<?>... typeArgs)`, который:
     - Создает `ArrayList<String>` при вызове: `createGenericCollection("ArrayList", String.class)`
     - Создает `HashMap<Integer, Double>` при вызове: `createGenericCollection("HashMap", Integer.class, Double.class)`
     - Создает `List<List<String>>` при вызове: `createGenericCollection("ArrayList", ParameterizedTypeImpl.make(List.class, new Type[]{String.class}, null))`

4. **Работа с обобщенными методами:**
   - Создать класс `GenericMethods` с методами:
     - `<T> List<T> createList(T[] array)`
     - `<K extends Comparable<K>, V> Map<K, V> createSortedMap(List<K> keys, List<V> values)`
   - Реализовать метод `invokeGenericMethod(Object instance, String methodName, Class<?>[] typeParams, Object[] args)`, который:
     - Вызывает `createList` с конкретным типом `String`
     - Вызывает `createSortedMap` с типами `Integer` и `String`

**Конкретные примеры для реализации:**

- **Пример 1:** Проанализировать класс `java.util.Collections$UnmodifiableMap` и определить его типовые параметры.
- **Пример 2:** Создать экземпляр `ConcurrentHashMap<String, List<Integer>>` через Reflection.
- **Пример 3:** Определить фактические типы в поле `Map<String, List<Set<Integer>>> complexField`.

**Требования к реализации:**

- Поддержка основных обобщенных типов Java Collections Framework
- Обработка пользовательских обобщенных классов с вложенными типами

- Логирование ошибок типа и исключений с понятными сообщениями

#### Задание 3: Изменение final полей и обход инкапсуляции

   - Показать проблемы с `HashMap`: изменить `hashCode` объекта после помещения в map

**Конкретные примеры для реализации:**

#### Задание 6: Генерация классов во время выполнения

**Цель:** Освоить техники динамической генерации байт-кода, создания классов во время выполнения и их загрузки в различные classloader'ы с использованием библиотек байт-код инжиниринга.

**Задача:** Создать класс `ClassGenerator`, который использует библиотеку **Javassist** или **ASM** для следующих конкретных сценариев:

1. **Генерация POJO (Plain Old Java Object) класса:**
   - Реализовать метод `generatePojoClass(String className, Map<String, Class<?>> fields)`, который:
     - Создает класс с указанным именем и пакетом
     - Добавляет приватные поля согласно переданной карте (например: `{"name": String.class, "age": int.class, "score": double.class}`)
     - Генерирует геттеры и сеттеры для всех полей
     - Создает конструктор со всеми полями
     - Генерирует методы `equals()`, `hashCode()` и `toString()`
   - Пример использования: `generatePojoClass("Person", Map.of("name", String.class, "age", int.class))`

2. **Создание класса-декоратора для логирования:**
   - Реализовать метод `createLoggingDecorator(Class<?> targetInterface)`, который:
     - Создает класс, реализующий указанный интерфейс
     - Для каждого метода интерфейса генерирует реализацию, которая:
       - Логирует входные параметры
       - Вызывает исходный метод (переданный через конструктор)
       - Логирует результат выполнения
       - Логирует исключения, если они возникают
   - Пример: создать декоратор для `List<String>`, который логирует все операции добавления/удаления

3. **Генерация класса для вычисления математических выражений:**
   - Реализовать метод `generateCalculator(String expression)`, который:
     - Анализирует математическое выражение (например: `"a + b * c"`)
     - Создает класс `DynamicCalculator` с методом `calculate(double a, double b, double c)`
     - Генерирует байт-код, соответствующий выражению
     - Оптимизирует выражение (константная свертка, удаление лишних операций)
   - Пример: `generateCalculator("x * x + 2 * x + 1")` создает класс для вычисления квадратного уравнения

4. **Модификация существующего класса для добавление функциональности:**
   - Реализовать метод `addTimingToMethods(Class<?> clazz, String... methodNames)`, который:
     - Загружает байт-код указанного класса
     - Для каждого указанного метода добавляет измерение времени выполнения
     - Вставляет код для записи времени начала и окончания выполнения
     - Сохраняет результаты в статическое поле `Map<String, Long> executionTimes`
     - Перезаписывает оригинальный `.class` файл или создает новый класс-наследник

**Конкретные примеры для реализации:**

- **Пример 1:** Сгенерировать класс `Employee` с полями: `id (int)`, `fullName (String)`, `salary (double)`, `department (String)` и всеми стандартными методами.
- **Пример 2:** Создать динамический прокси для интерфейса `Runnable`, который считает количество выполненных задач.
- **Пример 3:** Сгенерировать класс `StringTransformer` с методом `transform(String input)`, который выполняет цепочку операций, заданную в конфигурации (например: `trim -> toUpperCase -> replace("A", "B")`).
- **Пример 4:** Модифицировать класс `ArrayList` для добавления статистики: сколько раз вызывались методы `add()`, `remove()`, `get()`.

**Требования к реализации с использованием Javassist:**

1. **Простой режим (Javassist):**
   - Использовать `ClassPool`, `CtClass`, `CtMethod`, `CtField`
   - Генерация методов через строки с Java-кодом
   - Простая компоновка классов через `CtClass.make()`

2. **Продвинутый режим (ASM):**
   - Использование `ClassWriter`, `MethodVisitor`, `FieldVisitor`
   - Генерация инструкций байт-кода напрямую
   - Оптимизация сгенерированного кода

**Динамическая загрузка и использование:**

- Реализовать `DynamicClassLoader` для изоляции сгенерированных классов
- Создать механизм "горячей замены" классов во время выполнения
- Реализовать сериализацию сгенерированных классов в файлы `.class`
- Создать реестр сгенерированных классов с возможностью их повторного использования

**Пример кода использования:**

```java

// Генерация POJO

    Map.of("name", String.class, "age", int.class));

    .newInstance("John", 30);

// Создание декоратора

    List.class, originalList);

// Генерация калькулятора

double result = calc.calculate(2.5, 3.0, 1.0); // 2.5*3.0 + 1.0 = 8.5
```
